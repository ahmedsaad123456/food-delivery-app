### Asynchronous Processing & Thread Management

- Configured a dedicated `ThreadPoolTaskExecutor` with custom core pool size, maximum pool size, queue capacity, and thread name prefix.
- Enabled asynchronous execution using `@EnableAsync` and moved notification processing to `@Async("orderExecutor")`.
- Verified that async tasks run on separate threads from the request thread.
- Identified that `SecurityContextHolder` and MDC context are not automatically propagated to async threads.
- Implemented a `TaskDecorator` to propagate the security context and MDC data to async threads, with proper cleanup after execution.
- Used `CompletableFuture` to execute ETA calculation, driver assignment, and notifications concurrently after payment confirmation.
- Added asynchronous error handling using `exceptionally` and `handle`.
- Verified that Spring transactions do not automatically propagate to methods executed on separate `@Async` threads using `TransactionSynchronizationManager.isActualTransactionActive()`.
